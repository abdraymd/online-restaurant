# Backend Plan — Online Restaurant Ordering Platform

## 1. Tech Stack

| Concern | Choice | Rationale |
|---------|--------|-----------|
| Runtime | Node.js 20 LTS | Ubiquitous ecosystem, fast I/O |
| Framework | Express 4 | Minimal, easy middleware |
| Database | PostgreSQL 16 | Relational integrity, ACID transactions for orders |
| ORM | Prisma 5 | Type-safe queries, auto-migrations, clean schema DSL |
| Auth | JWT (jsonwebtoken) + bcrypt | Stateless; bcrypt for password hashing |
| Validation | Zod | Schema-first, composable, TypeScript-native |
| Language | TypeScript 5 | Catches contract bugs early; Prisma generates full types |
| Testing | Vitest + Supertest | Fast unit/integration tests |
| Dev server | ts-node-dev | Hot-reload in dev |

## 3. Data Models (Prisma Schema)

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

enum Role {
  CUSTOMER
  RESTAURANT_OWNER
  ADMIN
}

enum OrderStatus {
  PENDING
  CONFIRMED
  PREPARING
  READY
  DELIVERED
  CANCELLED
}

model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String
  name         String
  role         Role     @default(CUSTOMER)
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  orders       Order[]

  @@index([email])
}

model Restaurant {
  id          String   @id @default(cuid())
  name        String
  description String?
  imageUrl    String?
  address     String
  phone       String?
  isOpen      Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  menuItems   MenuItem[]
  orders      Order[]

  @@index([isOpen])
}

model MenuItem {
  id           String   @id @default(cuid())
  restaurantId String
  name         String
  description  String?
  price        Decimal  @db.Decimal(10, 2)   // store money as DECIMAL, never FLOAT
  imageUrl     String?
  isAvailable  Boolean  @default(true)
  category     String?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  restaurant   Restaurant  @relation(fields: [restaurantId], references: [id])
  orderItems   OrderItem[]

  @@index([restaurantId])
  @@index([restaurantId, isAvailable])
}

model Order {
  id           String      @id @default(cuid())
  userId       String
  restaurantId String
  status       OrderStatus @default(PENDING)
  totalPrice   Decimal     @db.Decimal(10, 2)
  note         String?
  createdAt    DateTime    @default(now())
  updatedAt    DateTime    @updatedAt

  user         User        @relation(fields: [userId], references: [id])
  restaurant   Restaurant  @relation(fields: [restaurantId], references: [id])
  items        OrderItem[]

  @@index([userId])
  @@index([restaurantId])
  @@index([status])
}

// unitPrice snapshots the price at order time — historical totals stay correct
// even when menu prices change later
model OrderItem {
  id         String   @id @default(cuid())
  orderId    String
  menuItemId String
  quantity   Int
  unitPrice  Decimal  @db.Decimal(10, 2)

  order      Order    @relation(fields: [orderId], references: [id], onDelete: Cascade)
  menuItem   MenuItem @relation(fields: [menuItemId], references: [id])

  @@index([orderId])
}
```

## 4. API Endpoints

Base path: `/api/v1`  
**Public** routes need no token. **Protected** routes require `Authorization: Bearer <token>`.

### Auth — Public

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | /auth/register | No | Create account, returns JWT |
| POST | /auth/login | No | Authenticate, returns JWT |
| GET | /auth/me | Yes | Get current user profile |

**POST /auth/register** body: `{ name, email, password, role? }`  
**POST /auth/login** body: `{ email, password }`  
Both return: `{ token, user: { id, name, email, role } }`

### Restaurants — Public

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | /restaurants | No | List all restaurants (paginated, filterable) |
| GET | /restaurants/:id | No | Single restaurant + menu preview |
| POST | /restaurants | No | Create restaurant |
| PATCH | /restaurants/:id | No | Update restaurant |
| DELETE | /restaurants/:id | No | Delete restaurant |

GET /restaurants query params: `search`, `isOpen`, `page` (default 1), `limit` (default 20, max 100)  
Response shape: `{ data: [...], meta: { page, limit, total } }`

### Menu Items — Public

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | /restaurants/:restaurantId/menu-items | No | List menu |
| POST | /restaurants/:restaurantId/menu-items | No | Add item |
| PATCH | /menu-items/:id | No | Update item |
| DELETE | /menu-items/:id | No | Delete item |

Query params for GET: `category`, `isAvailable` (default true)

### Orders — Protected

All order endpoints require a valid JWT. `userId` is always taken from the token — never from the request body.

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | /orders | **Yes** | Place order |
| GET | /orders | **Yes** | List orders (scoped to authenticated user) |
| GET | /orders/:id | **Yes** | Order detail |
| PATCH | /orders/:id/status | **Yes** | Update status |
| DELETE | /orders/:id | **Yes** | Cancel (PENDING only) |

**POST /orders** body:
```json
{
  "restaurantId": "...",
  "items": [{ "menuItemId": "...", "quantity": 2 }],
  "note": "Extra napkins"
}
```
**Rules**: all menuItemIds must belong to restaurantId and be available; `totalPrice` computed server-side — never trust client prices.

### Users — Admin Only

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | /users | Yes (ADMIN) | List all users |
| GET | /users/:id | Yes (ADMIN) | Get user |
| DELETE | /users/:id | Yes (ADMIN) | Delete user |

### Error Response Shape

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "price must be a positive number",
    "details": []
  }
}
```
Standard codes: `VALIDATION_ERROR`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `INTERNAL_ERROR`

## 5. Step-by-Step Implementation Order

### Phase 1 — Project Scaffold
1. `npm init -y` inside `backend/`
2. Install runtime deps:
   ```
   npm install express prisma @prisma/client jsonwebtoken bcrypt zod cors helmet express-rate-limit
   ```
3. Install dev deps:
   ```
   npm install -D typescript ts-node-dev @types/express @types/node @types/jsonwebtoken @types/bcrypt vitest supertest @types/supertest
   ```
4. Create `tsconfig.json` (target ES2022, strict true, outDir `dist/`)
5. Create `vitest.config.ts`
6. Add scripts to `package.json`: `dev`, `build`, `start`, `test`, `db:migrate`, `db:studio`
7. Create `.env`, `.env.example`, `.gitignore`

### Phase 2 — Database + Prisma
8. `npx prisma init`
9. Paste full schema from Section 3 into `prisma/schema.prisma`
10. `npm run db:migrate -- --name init`
11. Create `src/lib/prisma.ts` — singleton PrismaClient

### Phase 3 — Core Middleware
12. `src/config.ts` — validate env vars with Zod
13. `src/app.ts` — mount helmet, cors, express.json(), rate limiter
14. `src/middleware/errorHandler.ts` — maps error classes to HTTP codes; handle Prisma P2025→404, P2002→409
15. `src/middleware/validate.ts` — factory `validate(schema)` for Zod request validation
16. `src/lib/jwt.ts` — `signToken` / `verifyToken`
17. `src/middleware/auth.ts` — `requireAuth` + `requireRole(...roles)`
18. `src/types/express.d.ts` — augment `Request` with `user`
19. `src/index.ts` — call `app.listen(config.PORT)`

### Phase 4 — Auth Module
20. `auth.service.ts` — `register()` (hash pw, create user, sign JWT), `login()`, `getMe()`
21. `auth.controller.ts` + `auth.router.ts`
22. Mount at `/api/v1/auth`
23. Write `tests/auth.test.ts`

### Phase 5 — Restaurants Module
24. `restaurants.service.ts` — list, findById (includes menuItems), create, update, remove
25. Controller + router, mount at `/api/v1/restaurants`
26. Write `tests/restaurants.test.ts`

### Phase 6 — Menu Items Module
27. `menu-items.service.ts` — listByRestaurant, create, update, remove
28. Controller + router (nested GET/POST, flat PATCH/DELETE)
29. Write `tests/menu-items.test.ts`

### Phase 7 — Orders Module
30. `orders.service.ts`:
    - `placeOrder` — validate items belong to restaurant + are available, compute totalPrice, create Order + OrderItems in `$transaction`
    - `list` — scoped to `req.user.id`
    - `findById` — verifies ownership via `req.user.id`
    - `updateStatus` — same ownership check
    - `cancel` — only PENDING orders
31. Apply `requireAuth` to all order routes in `orders.router.ts`
32. Controller + router, mount at `/api/v1/orders`
33. Write `tests/orders.test.ts`

### Phase 8 — Users Module (Admin)
34. `users.service.ts`, controller, router (all routes `requireRole('ADMIN')`)
35. Mount at `/api/v1/users`

### Phase 9 — Hardening
36. Wrap all async handlers (use `express-async-errors` package)
37. Review all Zod schemas (required fields, min/max, price > 0, quantity >= 1)
38. `npm test` — all green
39. `npm run build` — zero TypeScript errors

## 7. How to Run Locally

### Prerequisites
- Node.js 20 LTS, npm 10+
- PostgreSQL 16 (local or Docker)

### Start PostgreSQL via Docker (recommended)
```bash
docker build -t restaurant-pg ./docker
docker run --name restaurant-pg -p 5432:5432 -d restaurant-pg
```

Or with plain postgres image (no seed data):
```bash
docker run --name restaurant-pg \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=password \
  -e POSTGRES_DB=restaurant_db \
  -p 5432:5432 \
  -d postgres:16-alpine
```

### Start the Dev Server
```bash
cd backend
npm install
npm run db:migrate   # creates tables, generates Prisma Client
npm run dev          # hot-reload on port 3000
```

### Run Tests
```bash
npm test
```

### Inspect Database (GUI)
```bash
npm run db:studio    # Prisma Studio at http://localhost:5555
```

### Build for Production
```bash
npm run build && npm start
```

## Key Design Decisions

| Decision | Reason |
|----------|--------|
| Prisma over Sequelize/TypeORM | Best TypeScript experience; schema-as-code migrations are auditable |
| JWT (not sessions) | Stateless; no Redis required for MVP |
| Auth required for orders only | Restaurants and menu items are public read/write — only orders need an identity anchor |
| DECIMAL for money | Float arithmetic causes cents rounding bugs |
| `unitPrice` snapshot on OrderItem | Preserves historical totals when menu prices change |
| Server-side total calculation | Prevents price manipulation from client |
| Prisma `$transaction` for order creation | Atomicity — either all items save or none |
