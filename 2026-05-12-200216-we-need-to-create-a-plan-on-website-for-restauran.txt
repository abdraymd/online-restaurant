     browse a list of restaurants, view menus, and place orders. Four engineers

     ---
     Per-Role Summary

     Backend (backend/) — Node.js + Express + TypeScript + PostgreSQL + Prisma

     - Auth: JWT + bcrypt, roles: CUSTOMER / RESTAURANT_OWNER / ADMIN
     - Models: User, Restaurant, MenuItem, Order, OrderItem (with price
     snapshot)
     - API (base /api/v1): /auth, /restaurants, /menu-items, /orders, /users
     - Port: 3000
     - Key rule: totalPrice computed server-side; money stored as DECIMAL(10,2)
     - Implementation phases: scaffold → DB/Prisma → middleware → auth →
     restaurants → menu-items → orders → users → hardening
     - Env vars: DATABASE_URL, JWT_SECRET, JWT_EXPIRES_IN, CORS_ORIGIN, PORT

     Frontend (frontend/) — React 18 + Vite + TypeScript + Tailwind + shadcn/ui

     - State: Zustand (cart + auth, persisted to localStorage) + TanStack Query
     (server data)
     - 7 pages: Home, Restaurant Detail, Checkout, Order Confirmation, Order
     History, Login, 404
     - 15 components: RestaurantCard, RestaurantGrid, SearchBar, MenuItemCard,
     MenuItemModal, CategoryFilter, CartDrawer, CartItem, OrderSummary,
     OrderStatusBadge, CheckoutForm, Navbar, Footer, AuthGuard, LoadingSpinner
     - API layer: Axios instance in src/api/client.ts with auth interceptor; all
      fetchers typed
     - Cart rule: single-restaurant enforcement; prices stored in cents
     - Env vars: VITE_API_BASE_URL, VITE_AI_API_BASE_URL

     AI (ai/) — Python + FastAPI microservices

     - 5 features:
       a. Semantic Search (port 8001) — text-embedding-3-small + Chroma vector
     DB
       b. Chatbot Ordering Assistant (port 8002) — GPT-4o + function calling
       c. Review Sentiment Analysis (port 8003) — GPT-4o-mini classifier
       d. Smart Upsell Engine (port 8004) — co-occurrence matrix from orders
       e. Personalized Recommendations (port 8005) — ALS collaborative filtering
      (implicit lib)
     - Build order: Search → Chatbot → Sentiment → Upsell → Recommendations
     (data-hungry features last)
     - Integration: backend proxies calls to AI services via X-Service-Key
     header
     - Env vars: OPENAI_API_KEY, CHROMA_PATH, SERVICE_KEY, BACKEND_API_URL

     QA (qa/) — Jest + Vitest + Playwright + Newman + k6 + OWASP ZAP

     - Testing pyramid: unit → integration → API contract (Newman) → E2E
     (Playwright) → performance (k6) → security (ZAP)
     - Critical test IDs: AUTH-01–12, REST-01–10, MENU-01–07, ORD-01–13,
     AI-01–07, REC-01–06
     - Quality gates: 80%+ coverage, 0 Newman failures, 0 Playwright failures
     (Chrome + Firefox), p95 < 200 ms, 0 ZAP HIGH alerts
     - CI: GitHub Actions workflow at .github/workflows/qa.yml — jobs run in
     parallel where possible
     - Implementation order: scaffold → unit (backend) → unit (frontend) →
     integration → Newman → Playwright → k6 → ZAP → CI wiring

     ---
     Verification

     After implementation, end-to-end test:
     1. Start Postgres + backend (npm run dev in backend/)
     2. Start AI services (uvicorn main:app --reload in each ai/service-*/)
     3. Start frontend (npm run dev in frontend/)
     4. Browse to http://localhost:5173, register a user, browse restaurants,
     add items, place order
     5. From qa/: run npm run test:all — all suites green
